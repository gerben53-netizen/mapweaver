# Local service security and privacy

Open data folder is an explicit Windows UI action using the system Explorer executable, no shell and only the validated storage directory. There is no arbitrary command or path parameter.

The service is an application for one local OS user, not a remotely hosted API. It binds **127.0.0.1 only**. No accounts, cloud sync, telemetry, external image URLs, browser filesystem paths or arbitrary file-serving endpoint are added. Other processes running as the same OS user can access their files; this is not a boundary against local malware or administrators.

Host validation prevents DNS rebinding; Origin must match the service or one explicitly configured local development origin. Cross-site Fetch Metadata requests are refused. Mutations need a non-simple `X-Mapweaver` header; there is no permissive CORS/preflight handler. Development origin configuration accepts only an exact `http://127.0.0.1:<port>` or `http://localhost:<port>` origin. Do not expose the process through a reverse proxy/tunnel or bind a development proxy to the LAN.

Image imports are bounded and decoded by Sharp after signature/dimension validation. Only PNG/JPEG/WebP are accepted; animation/multipage images are rejected. ZIP import reuses the existing path, entry/count/size/ratio, CRC, reference, type and checksum validation. Archive names never become managed paths. SHA-256-generated filenames and containment/symlink checks protect managed data. Uploaded images are served as raster data with correct MIME and nosniff; no HTML/SVG uploads execute.

SQLite uses parameterized queries, foreign keys and transactions. Revision checks prevent silent stale overwrites. A failed save remains dirty/conflict/error and is not labelled saved. The browser retains current model state and attempts an independent unsynced recovery buffer. Editing while offline is not a guarantee against browser crashes: keep the window open, reconnect and save, or explicitly export a project if all required image bytes are available.

No request logger is enabled. Structured errors omit SQL, native error text and absolute paths. Storage location is intentionally shown only in the requested local Storage UI/API. Logs never include image bytes. Startup reports only a generic integrity-attention message, with details available locally. Missing/damaged images block successful save/export/backup; orphan and temporary files are reported and retained, not silently removed.

Full backups now stream SQLite snapshots and immutable assets to ZIP64, with checksums and a complete isolated verification pass before publishing the archive. Restore supports older full backups, rejects unsafe/duplicate/missing entries and bombs, stages on the same volume, validates actual images and SQLite, and uses a retained rollback directory plus crash-recovery journal. Dataset generation checks guard mutations both on arrival and after waiting for the write queue. External origins/hosts and cross-site fetch metadata remain refused; mutations require custom headers and no permissive CORS is enabled.

Diagnostics include only safe versions, counts, sizes and generic status. No user paths, names, documents, images, full database, browser data or request logs are included. Launcher and package require no account/network/runtime installation, and never silently choose another data directory. A local safety-port lease excludes another production writer; unrelated port collisions fail safely. Recovery points are conservatively retained, with no automatic cleanup.

Validation uses synthetic assets, test-only temporary directories and isolated Chrome/Edge contexts. The installed antivirus injected external URLs into a first Chrome test; no Mapweaver code initiated them. Subsequent acceptance tests block all non-loopback requests in their own context without changing antivirus settings. Do not interpret a browser extension/antivirus injection as application telemetry, or claim that application code can control such software.


Sprint 13.1 adds a runtime instance UUID independently of the persistent dataset generation. Production mutations require both the custom request headers and the current instance UUID; a restart cannot revive an old tab's authority. Supervisor control additionally requires a random per-launch token inherited through the child environment, never returned by health. Browser Stop requires a registered current-instance client and the same origin protections. Current browser clients may choose Wait or Keep running during their own stop workflow.

Supervisor discovery and generation-specific command pipes use an explicit current-user SID ACL, deny network logons, bound messages to 160 ASCII bytes and two seconds, and allow only open/stop/restart/status. The lifetime mutex owns only the supervisor: the existing Node safety lease still owns writer exclusion. No stale filesystem lock is deleted. See [portable lifecycle](portable-lifecycle.md). No new npm or tray/IPC dependency was added; the launcher uses the existing .NET Framework WinForms and OS primitives.
