# Full backup format 2 and restore protocol

Format 1 (Sprint 12, ZIP STORE, schema 1/2) is still accepted. Format 2 is ZIP64 STORE and contains only manifest.json, mapweaver.sqlite3, hash-named originals and previews. The manifest has formatVersion, schemaVersion, appVersion, createdAt, dataset generation, sourceBytes, archiveBytes (fixed-width decimal string), project/asset counts, compression=store, complete=true and a path→size/SHA-256 map. Absolute paths, OS usernames and runtime configuration are not portable. Safe dataset settings remain in SQLite; restore replaces the generation token.

Limits: 256 GiB default configurable archive/source limit, 100,001 entries, 160-character allowlisted paths, 32 MiB manifest, 200:1 expansion, no encrypted entries, no symlinks, no duplicate names, only STORE/DEFLATE. New archives use STORE and ZIP64. The manifest is read and all central-directory metadata checked before extracting. Streaming extraction verifies actual sizes and hashes, then compares the manifest to the database's exact referenced file set. Unregistered orphan files are not silently adopted. Sharp decodes each bounded raster; SQLite is first read-only with integrity_check, foreign_key_check, schema checks, no triggers/views/virtual tables, parsed projects, relations and sizing metadata validation.

Backups serialize writes, use the official SQLite backup API, hash files in 256 KiB chunks, stream a temporary archive, fsync, verify it by streamed extraction and full isolated validation, then rename to the final owned archive. The manifest's fixed-width archiveBytes is populated using yazl's size calculation before its lazy manifest stream begins. No complete archive is held in memory. Browser destinations use streamed writes where available; native downloads remain browser-controlled. Free space is checked before snapshot/extraction and during archive/upload writes. Temporary archive errors are not success.

Restore stages on the active directory's volume. The user reviews filename/date and confirms replacing all local data. Writes are then blocked; staging is migrated and assigned a new random datasetGeneration; live SQLite checkpoints and closes. A durable journal records prepared → installed → committed while the live directory is renamed to a rollback directory and staging becomes live. Windows has no single atomic exchange of two nonempty directories: each rename is atomic, the journal makes the pair recoverable. Reopen and validate before commit. Failure before commit restores the old directory; an interrupted process follows the same rollback journal on next startup. Failure to recover halts startup with both datasets retained. Recovery points are not automatically deleted.

The local threat boundary excludes other malicious processes already running as the same OS user; there is no claim to defend against an administrator modifying files between checks. See local-service-security.md. No merge of whole datasets is offered.

Sprint 15: the backup container and SQLite schema are unchanged. Dataset validation accepts canonical project v4 paths, including bounded geometry and fillPattern texture references, through the same project parser. Restore into an older application that cannot read v4 is unsupported.

Schema 7 adds campaign/node metadata. These tables, campaign preferences, recent-open timestamps and retained Trash participate in the same database snapshot. Dataset validation checks hierarchy limits, parent folders, cycles, unique references and that each project belongs to a campaign before restoration. The backup archive format remains version 2. Dedicated single-campaign merging/import is not part of whole-dataset Restore.
