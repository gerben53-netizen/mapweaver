# ADR 0019 — Reusable library compositions

Accepted for Sprint 23B, 24 September 2026.

Acceptance: capture selection/object group/layer/layer subtree without changing the source; explicitly handle inherited hidden/locked content and external references; save Editable and Flattened in the existing library; place independent copies with anchor, uniform physical scaling, supported layer choices and one undo; transfer complete dependencies and preserve them through backup/restore. Validate the browser workflow and deliver a separately built Windows package.

The actual baseline is project format 12 and SQLite schema 5. Object groups are nonnested same-layer ID collections and have no independent transform. Layer groups carry visibility/lock/order only. All geometric group transforms are already baked into ordinary objects. There is no additional parent matrix to apply during prefab normalization.

SQLite schema 6 extends the existing asset register with the `prefab` type and a nullable JSON `prefab` column. The row owns the existing title, description, category, tags, favorites, collections, default size, timestamps and preview fields. There is one canonical row per composition. Its original/preview paths are ordinary validated images, never JSON disguised as an image. Immutable hash-named blobs can be shared with other rows. The ordinary type/hash uniqueness rule remains a partial unique index for image roles; compositions with identical previews may have different editable semantics.

Existing databases receive a consistent `pre-prefabs-UUID.sqlite3` recovery snapshot before the transactional create/copy/drop/rename migration. Foreign-key enforcement is disabled only around this startup transaction, the resulting references are checked before commit, and enforcement is restored in `finally`. User projects, IDs, assets and files are retained. Fresh empty databases need no recovery snapshot. Project format remains 12 because placed instances are existing ordinary objects.

Public asset manifest 2 adds a distinct `type: prefab` entry with an explicit version-1 `prefab` payload and a raster `file` for its preview. Manifest 1 and existing stamp/sidecar behavior remain supported. The payload contains a canonical project-format-12 composition document, nominal/visible bounds, local anchor, source-map scale metadata and render scale. Source project identity is replaced with an independent composition identity; no path or live source-project relationship is stored. Flattened payloads contain one ordinary stamp, not retained editable source objects.

Object relationships (opening wall, label owner, room provenance walls, explicit path junction targets) are separate from asset dependencies. Capture deduplicates descendants. Required-object closure is explicit and capped at 256 additions; hidden targets require the hidden-content option too. Unresolved relationships block saving. Explicit optional detachment removes external label ownership/leader, room provenance or junction annotations while retaining concrete geometry; openings always require their wall. Unknown objects are rejected by the existing parser. Clipping/Scatter masks are already copied geometry, not external references. All object, node, junction-target, layer, group and legend-entry IDs are remapped before whole-document validation. Recapturing an instance captures its ordinary objects, never another prefab reference.

Images resolve through the existing plural object-asset adapter, canonical image manifests and immutable wall material definitions embedded in wall objects. A wall atlas includes body/cap/join images; no separate mutable wall-set lookup is needed to render an instance. Text uses the existing format-pinned bundled Liberation fonts, shipped with the application. There is no external font URL or prefab dependency type. A prefab entry cannot satisfy an image dependency; recursive prefab graphs and unknown payload versions fail before commit.

Both save and portable import use Sprint 23's bounded preview, revision validation, rolled-back review, owned-file journal and atomic SQLite commit. Dependencies must all be present as validated ordinary image entries in the pack. Hash/type remapping happens after every image row is registered and before committing the composition. Cleanup preserves referenced/shared files. Usage scans include retained prefab definitions, so removing a prefab from the active library cannot make its recovery data incomplete. Full backups include definitions and all image rows; restore additionally validates the composition and dependency hashes/types/dimensions.

Capture normalizes geometry through the existing selection-transform rules. Rendering uses the existing PNG scene/painters with no background/overlays and grid disabled by default. Actual alpha determines crop, with two map-pixel antialias padding at either resolution; margins expand if artwork touches the render edge. Visible bounds and image map-size preserve the crop offset relative to the anchor. Pixel resolution is never the prefab's native placement size. Existing renderer/resource limits remain authoritative.

Placement uses uniform similarity transforms around the stored anchor. Native means stored composition dimensions; grid/world modes use the Sprint 23 resolver and retain its explicit fallback explanation. Active-layer placement bakes inherited visibility/locking into object flags, keeping paint order and object groups. Preserve-layers placement copies the tree into a new group (reusing its new copied root group where possible to avoid wasting depth). Existing nonnested same-layer groups cannot represent one cross-layer object group; all new objects are selected and existing internal groups remain editable. Placement validates the complete target and its metadata budget before one editor-history transaction.

Limits: 2,000 ordinary objects, 128 layers, 512 image dependencies, 4 MiB payload, existing five-level layer tree, 256 explicit required additions; 1,000 manifest entries/128 MiB pack; existing 5,000 scatter instances/object and 10,000/document; existing 32-million render pixels, 16,384 edge and 512 MiB working estimate. No new live components, nested prefab object type or general effects engine.

Library listings fetch only metadata and small JSON summaries; full compositions are fetched only for placement/export. Metadata history stores no immutable prefab payload and its UPSERT undo leaves that column intact.
