# ADR 0011 — Specialized walls on the shared path engine

Accepted 24 September 2026, implementing the supplied Sprint 17 brief. No doors, windows, openings, room inference, floors or persistent wall graph are introduced.

A wall is a canonical `kind: path`, `pathKind: wall` object. Nodes, relative handles, closed state, thickness (`strokeWidth`), opacity, cap and join reuse the path contract. The optional `wall` member is required for wall paths and forbidden on generic paths at runtime admission. It contains a unit reference, texture flip and outline. Concrete style is stored; presets are editor conveniences, never external mutable dependencies. Generic paths retain their existing renderer and semantics.

Format 6 is the first wall format. Existing v1–v5 readers remain centrally normalized; historical compatibility is not required. SQLite tables, asset manifests and ZIP containers do not change. Images remain typed fillPattern references, covered by the existing reference retention/remapping/backup paths. There are no tile objects, generated texture blobs or persisted contours.

The map has no physical scale until the later Regional/World sprint. Wall settings therefore explicitly store `unit` and positive `pixelsPerUnit`. Pixels use 1; choosing grid cells captures the current grid size; feet/metres require an editable reference (initially 70 px/unit). Changing the reference alone does not change canonical thickness or geometry. Changes to the grid do not silently resize existing walls. Physical length is meaningful only relative to this explicit reference, not a newly inferred global map scale.

Solid walls use exact native cubic strokes with miter limit 2 and all three cap/join choices. Textures use bounded adaptive centerline samples and a derived contour, split into tangent-oriented strips with common bisector boundaries. The pattern repeats continuously along cumulative sampled arc length; its stored offset is retained when nodes change. It clips to the contour; the outline uses the same exact cubic stroke as a solid wall. Each wall has one Konva Shape. Editor and PNG call the same painter. Derived geometry and browser Path2D contours are weakly cached by immutable wall object identity.

Separate compatible open endpoints receive transient round visual junction patches. These do not merge IDs, split T targets or change nodes. Explicit Continue/Extend uses the existing object and one history entry only when the layer/style and editable endpoint match. Ordinary snapping always creates a separate object. Hidden and locked targets are excluded from snapping; persisted visibility controls rendering/export. The existing node editor, history, grouping and layers remain authoritative.

Transforms bake nodes and handles. Uniform scale changes thickness and outline by the same factor; texture scale/offset and the unit reference remain explicit style values. The controlled nonuniform same-size operation uses the smaller scale for thickness/outline; invalid or excessive geometry is refused atomically. This is not a width-profile or perspective wall model.

Limits: 256 nodes/wall, 8,192 adaptive samples, 1,000,000 map-pixel length, thickness >0 through 1,024 px, outline 0–128 px, bulk 1–100 walls; existing document-wide node/sample/metadata budgets apply. Snap tolerance is eight screen pixels. Miter spikes fall back to bevel beyond 2 radii. No new geometry dependency is necessary.

Texture boundaries: assets should be opaque and repeatable; fillPattern is the existing semantic asset type, not a promise that arbitrary uploaded edges are seamless. Sharp joins may have a visible phase seam. Closed loops need not contain an integer number of repeats. Cusps, self intersections and nearly reversing segments may overlap texture patches; this is a visual wall stroke, not polygon topology or a manifold solid. Raster antialiasing can reveal fine strip seams at extreme zoom. These limitations do not affect canonical geometry, hit testing or undo, and editor/export share them. Custom is session-only; no preset library is added.
