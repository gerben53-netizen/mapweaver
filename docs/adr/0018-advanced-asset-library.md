# ADR 0018 — Hierarchical asset library and placement defaults

Status: accepted for Sprint 23, 24 September 2026.

SQLite schema 5 is authoritative for the shared library. Existing project format 12 stores concrete object transforms and immutable image references. Library metadata does not participate in rendering an existing document. Format 12 gains the optional `map.grid.physicalScale: { distancePerCell, unit: ft | m }`; absent means unconfigured, never an assumed real-world scale. Older application binaries are not supported readers of this extension.

Categories are virtual rows with stable UUIDs, parentId, sortOrder and timestamps. The reserved `uncategorized` row is not a parent. Maximum depth is eight, counting a root as one. Every tree mutation validates the complete resulting ancestry and normalized sibling names. NFKC, trim and en-US lowercasing define case-insensitive keys; SQL's existing unique normalizedName stores a parent-qualified key. Migration retains old root keys; subsequent edits canonicalize them. Categories never select or create filesystem directories.

The migration uses `VACUUM INTO backups/pre-library-<UUID>.sqlite3` before changing an existing database. This consistent recovery point references the same immutable originals/previews, which migration never modifies or removes. Existing flat categories become roots. Existing IDs, role associations, reserved sizing fields and project JSON are preserved. SQLite backup/restore includes all new columns, categories, collection membership and revision triggers. Backup validation permits only the twelve exact application-owned revision triggers, not arbitrary triggers or views.

Assets keep their existing one-item-per-type/hash identity. Hash deduplication shares bytes; stamp and fill-pattern are distinct logical rows with independent metadata. New fields are description, favorite, author, source, license, applicableMapTypes and retained deletedAt. Existing sizing columns remain the canonical representation, exposed in the public pack as defaultSize. Collections are name/description rows plus asset-ID memberships.

Library commands run in the existing serialized service mutation queue. A database revision, incremented by application-owned triggers, protects drafts and import previews against other tabs, including legacy API writes. Library history is separate from editor history: ten bounded row-delta entries per running service, with current-row comparison as well as request revision checking on undo. It cannot undo over newer edits of the affected rows. A service restart expires this UI history, not saved metadata. Editor shortcuts and toolbar controls follow the active workspace.

A pack is fully decoded and validated in a bounded, expiring service preview. Review resolved changes executes the proposed metadata transaction and rolls it back, displaying the resulting titles, categories, tags and sizes. The real commit repeats revision and validation checks. Original and preview files are atomically written before registration in one SQLite transaction. A flushed owned-path journal precedes new file writes. After failure/startup recovery, only journaled paths without database references are removed; pre-existing/shared blobs remain. A committed database with a surviving journal retains its referenced files. Previews expire after fifteen minutes; one current preview per service bounds memory. Preparing another pack replaces the previous preview.

`placementSize` is the shared new-stamp/scatter size resolver. Native preserves the original natural-pixel / maximum-quarter-of-map behavior. Grid uses configured battlemap pixels per cell. World converts feet by exactly 0.3048 metres and uses explicit battlemap distance per cell or the geographic pixels-per-kilometre service. Applicable map types are an array; empty means any. Missing/inapplicable scale produces a visible native-fallback explanation. Positions are snapped separately. Existing scatter recipes, pattern tile scales, material core widths and saved transforms are never reinterpreted. Capturing a selection uses object-local dimensions, where supported group transforms are already baked in. Reset retains centre, rotation and mirrors, skips unsuitable/locked objects and is one editor transaction.

Search/filter/sort is performed on the service over the complete active type dataset, with stable ID tie-breaking. A single indexed asset scan and precomputed ancestry/count maps avoid per-asset descendant or usage queries. Only bounded pages and their lazy thumbnails reach the browser. This deliberately uses an in-service normalized comparator instead of SQLite's limited Unicode NOCASE behavior; the measured 10,000-record workload is recorded in the sprint report. No renderer rewrite or cloud index.

Public assets schema version 1 is documented in `docs/asset-library.md`. Additional roles for Sprint 23B require an explicit new runtime contract and dependency validation; unknown types are refused today. Prefabs are not implemented. Wall sets retain their specialized contract; generic library export refuses an atlas registered as a wall set and directs users to retain/use the original complete wall-set ZIP. No second wall-set importer.

## Asset removal recovery amendment — 24 September 2026

Removal distinguishes persistent map/wall-set/prefab dependencies from transient editor references. Persistent dependencies block the whole transaction; clipboard/history/tool state does not. The service detaches memberships and mutable metadata while retaining tombstone identity and immutable bytes. Re-import revives that identity with fresh incoming metadata, preserving active duplicate policies. Matching normalized collection names and descriptions reuse collection rows. No SQLite, asset-pack or project version change is needed.

After successful commit the initiating editor removes affected clipboard assemblies and invalidates its history only when affected. Full snapshots make isolated history-entry pruning unsafe; clearing both directions preserves the dirty baseline. Library history remains the explicit full-library restoration mechanism and rechecks persistent use before a reverse action removes assets. Cleanup does not coordinate transient buffers in another already-open browser editor; retained bytes keep its existing document readable. See the asset-library guide and asset-removal recovery sprint report.
