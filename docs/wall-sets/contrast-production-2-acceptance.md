## Revision coexistence and selection

The immutable registry is bounded by 16 semantic material IDs and 16 revisions per material, replacing the former limit of 16 total records. This allows historical revisions to coexist without one-off material exceptions. Existing per-definition component limits still apply; conflicting duplicate identities remain rejected.

For new authoring, the highest admitted non-reference-only numeric `production-N` per semantic material is current. Selection is independent of registration order. Admission is an integration decision: rejected candidates must not be registered. Development/reference-only revisions stay hidden unless exactly referenced by the inspected wall. An explicitly selected historical revision remains available with a historical label; its stored ID/revision and rendering are never implicitly upgraded. `generatedWallStyle` without an explicit revision uses the current revision. Explicit revision requests always resolve exactly.

Partial promotion is supported: pale stone is current on production-2 while the four FIX sets remain on production-1. Canonical default content includes both new public resources and historical resolution, without user database reset, imports of test maps or rewriting existing objects. Generated Wall resources are bundled immutable content, not database library copies.
